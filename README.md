# Кворум — совет нейросетей

Текстовый MVP на русском без зависимостей. OpenAI, Grok, Mistral, Qwen, DeepSeek, Gemini, Claude. Выбор 2–7 участников, 2–5 раундов, остановка, экспорт Markdown. Ключи, задачи и ответы не сохраняются браузером. Экспортируйте обсуждение перед закрытием вкладки.

## Быстрый запуск

Node.js 22+: `npm start`, открыть http://localhost:8787. Для знакомства включить «Демо без API» — это явно обозначенные заглушки, не настоящие ответы.

Для настоящих ответов: «Подключения» → OpenRouter → личный API-ключ. Выбрать модели и запустить. Ключ находится в памяти вкладки и уходит только OpenRouter. Сначала проверьте небольшой задачей с двумя недорогими моделями. Идентификаторы моделей — редактируемые начальные значения, доступность и цены проверяйте у провайдера. Подписка ChatGPT/Grok и т.п. не включает API-баланс.

## GitHub Pages

Загрузите проект в отдельный репозиторий с веткой main. Settings → Pages → Source: GitHub Actions. Workflow pages.yml тестирует проект и публикует только public/. Приложение работает в подпапке репозитория. GitHub Pages обслуживает интерфейс; серверный Node.js-код там не исполняется. На Pages можно использовать OpenRouter из браузера или указать собственный HTTPS URL сервера-посредника.

## Прямые ключи провайдеров

Скопировать .env.example в .env, заполнить только нужные ключи и уникальный PROXY_TOKEN, запустить `node --env-file=.env server.mjs`. В «Подключениях» выбрать прямые API и ввести PROXY_TOKEN. На localhost поле URL оставить пустым; с Pages указать адрес своего HTTPS-сервера и добавить origin Pages (https://USERNAME.github.io, без пути) в ALLOWED_ORIGINS. Разместить Node.js за HTTPS reverse proxy; HOST=0.0.0.0 нужен только если хостинг требует внешний bind. Не публиковать .env.

Qwen использует международный DashScope endpoint. Ключи других регионов и сторонних перепродавцов могут требовать другого endpoint: меняется только фиксированная таблица providers в server.mjs. Модели редактируются через интерфейс.

Сервер принимает только известные провайдеры, проверяет origin и токен, ограничивает тело, время запроса и число одновременных обращений. Это личный прототип, не многопользовательская админка: для публичного платного сервиса нужны аккаунты, серверные квоты на пользователя, журнал расходов и защита от злоупотреблений. Токен посредника вводит только владелец, а не посетители с общим ключом.

## Пять протоколов

1. Консенсус: независимые ответы → взаимная критика → общий проект модератора → отдельное одобрение каждым. При возражении, ошибке или невалидном голосе консенсус не объявляется.
2. Голосование: ответы → доработка → JSON-голоса за финальные варианты → программный подсчёт → сборка победившего ответа. Ничья обозначается явно, компромисс формирует модератор.
3. Судья: независимые ответы → критика → вердикт выбранного участника.
4. Спор ролей: выбранным участникам по порядку назначаются оптимист, скептик, практик, идеалист, аналитик, редактор, пользователь. Затем модератор собирает итог.
5. Мозговой штурм: независимые идеи → развитие чужих идей → синтез.

Модератор выбирается среди участников. Раунды ограничены; автоматического бесконечного спора нет. В каждом раунде все видят одинаковый завершённый предыдущий контекст. Ошибка одного API не стирает ответы других. Общая стоимость зависит от моделей, длины контекста и количества раундов; интерфейс показывает число запросов, а не обещанную цену. Согласие моделей не гарантирует правильность. Нет веб-поиска и независимого фактчекинга.

## Проверка

`npm test` — независимость первого раунда, общий контекст последующих, подтверждение/отказ консенсуса, ничья, невалидные голоса, частичный сбой, отмена, авторизация и origin сервера. Реальные платные API требуют ключей и отдельно проверяются владельцем.

Документация API: https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request ; https://api-docs.deepseek.com/ ; https://docs.mistral.ai/api .
